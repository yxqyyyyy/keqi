# 将课期发布到 GitHub

GitHub 保存和分发源码。其他人下载后，需要在**自己的 Mac** 上安装依赖、配置自己的课程、登录自己的学习通或武汉大学希冀账号，并授权自己的 iCloud 日历。

把源码上传 GitHub 不会让程序自动成为公网网站。GitHub Pages 只能提供静态网页，不能运行本项目的 Python 后台、平台会话采集、macOS 自启服务或日历桥接。

## 1. 准备干净的源码包

在正在使用的项目目录运行：

```sh
python3 scripts/package_release.py
```

默认输出 `dist/keqi-source.zip`。工具根据源码白名单打包，不复制 `data/`、`.venv/`、`build/`、服务日志或本机凭据。先检查压缩包文件列表：

```sh
unzip -l dist/keqi-source.zip
```

将压缩包解压到一个**独立的新目录**，以下发布操作都在这个新目录进行，不在保存本人登录会话的运行目录操作。

公开前确认：

- 目录内没有 `data/`、浏览器会话、任务导出、截图、日志、私钥、`.env` 或个人访问链接。
- README 描述的是首次安装流程，不声称新使用者已经完成授权或登录。
- 保留 `THIRD_PARTY_NOTICES.md`，确认项目自身许可证。

`.gitignore` 只影响未跟踪文件，不能清除已经上传的内容或 Git 历史。如果曾把平台会话或其他凭据上传，删除当前文件不足以处理历史泄露；应停止继续发布、使相关会话失效，并另行清理历史。

## 2. 保留项目许可证

本项目由所有者确认采用 [MIT 许可证](../LICENSE)。再分发源码时保留 `LICENSE`，并保留 `THIRD_PARTY_NOTICES.md` 中的第三方原版权与许可声明。

官方仓库为 [yxqyyyyy/keqi](https://github.com/yxqyyyyy/keqi)。若把项目发布到自己的仓库，应保留已有许可文件，避免自动生成的文件覆盖原声明。

## 3. 创建自己的 GitHub 仓库

登录自己的 GitHub 账号，创建新仓库，填入自行选择的仓库名和说明。准备公开时选择 Public；如果仍在检查，可以先使用 Private。

有两种上传方式，任选一种。

### 使用 GitHub 网页

1. 打开刚创建的仓库，选择上传文件。
2. 上传第 1 步独立解压目录内的源码文件和子目录，保留目录结构。不要拖入原来的运行目录，也不要只上传一个 ZIP 代替可浏览的源码。
3. 检查待上传列表，确认包括 `.gitignore`、`README.md`、程序源码、脚本、文档和第三方声明。
4. 提交。需要同时提供压缩包时，可在仓库 Releases 中附上 `keqi-source.zip`，并说明需要在 Mac 本地安装。

### 使用 Git 命令行

在第 1 步独立解压出的源码目录打开终端。下面的 `<你的仓库地址>` 是占位文字，请替换为刚创建的仓库页面提供的地址；这些命令不会自动在 GitHub 创建仓库。

```sh
 git init
 git add .
 git status --short
```

先检查暂存文件列表，确认无个人数据，再继续：

```sh
 git commit -m "Initial source release"
 git branch -M main
 git remote add origin <你的仓库地址>
 git push -u origin main
```

这个流程面向刚创建的空仓库。若远端已经有 README、许可证或其他提交，应先正常克隆该仓库并把干净源码复制进去再提交，不要用强制推送覆盖。

## 4. 别人如何使用

使用者从仓库下载源码或克隆到自己的 Mac，按 [README](../README.md) 完成：

1. 安装 Python、采集依赖及 Xcode Command Line Tools，编译本机日历桥接。
2. 启动程序，在设置中填写自己的学习通作业、学习通考试和武大希冀课程关键词；不需要的类型留空。
3. 本人在平台原登录页登录自己的账号。只有缺年作业需要时才确认年份；不会复用发布者的课程、班级或登录状态。
4. 开启自己的 iCloud 日历，允许日历桥接访问，完成首次同步及通知核对。
5. 按需要安装登录自启服务，并在 iPhone、iPad 添加系统日历或 Scriptable 小组件。

首次使用不默认开启固定大物线下作业，需要的人自行开启。希冀地址当前固定为武汉大学部署，不适用于其他学校的希冀实例。

Mac 运行、联网且登录有效时，才能按计划读取和取消已完成提醒；已经到达设备的日历事件可继续由系统提醒。iCloud 和小组件更新可能有延迟。

## 5. 后续发布更新

每次先运行离线测试，再重新生成源码包，在干净目录检查变更并发布。不要把自己的数据库、会话或构建产物补进仓库；问题反馈也不要附带 Cookie、配对链接或包含个人任务的完整导出。

使用者更新前应保留自己本机的 `data/`，并先停止后台服务；将源码更新到原位置，按需要重新安装依赖或编译日历桥接，然后恢复服务。不要用别人的 `data/` 覆盖自己的目录。移动安装位置或重建 Python 虚拟环境后，需要重新安装自启服务。
