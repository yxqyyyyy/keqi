# 课期 · iPhone / iPad 小组件

这版小组件专门展示作业和考试，不含勾选或回传操作。它读取本机 Apple 日历中的“作业与考试”，展示由 Mac 程序写入、尚未完成的课期记录。脚本没有网络请求、文件读写、日历写入或通知创建。

## 展示设计

| 尺寸 | 内容 |
| --- | --- |
| 小号 | 最近 1 项课程、标题、提醒时间与倒计时 |
| 中号 | 最近 3 项，适合 iPhone 主屏幕 |
| 大号 | 最多 5 项，未来待办不足时补充最近逾期记录 |
| iPad 超大号 | 两列最多 8 项 |

日常使用暖白、低饱和绿，适配系统深色模式。**24 小时内待交作业使用暖橙卡片，顶部突出“24h 待交”数量；2 小时内使用红底白字、加大的剩余时间及“尽快提交”。**小号组件整块换色，中号、大号和超大号按任务逐行强调。考试单独标“待考”，线下作业标“线下待交”。这些状态以设备已同步的日历为准，不是直接查询平台。

48 小时内显示具体剩余小时，不足 1 小时显示分钟。考试按开考时间计算倒计时、排序和紧急颜色，并显示结束时间。考试进行中显示“考试中”，缺少开考时间显示“开考时间待补充”。固定大物线下作业在“周日 00:00”旁标注“周六 24:00 · 线下”（中号以具体日期时间为准）。全部时间固定显示北京时间，设备切换时区也不会改变。

近期安排按考试开考、作业截止和上课时间排列，进行中的考试优先显示。只有逾期时，中号在顶部标注“未来暂无 · 逾期”；大号额外标注“以下为逾期记录”，小号倒计时明确写“逾期”。确实没有目标记录时才显示空态。日历授权、找不到目标日历或读取失败会显示需要处理的提示，不会显示为“作业已完成”。

查询范围是**过去 30 天至未来 60 天**，逾期数量仅统计这 30 天。日历本身不提供平台实时提交状态；以 Mac 上次采集后写入、且已通过 iCloud 到达本机的记录为准。平台提交已被 Mac 检测并同步后，完成记录会从这个专用日历中移除。

## 安装到 iPhone 和 iPad

Mac 端可以先打开[小组件安装页](http://127.0.0.1:8765/widget.html)，查看外观并复制代码。手机先通过程序设置中的配对链接进入程序，再打开设置中的小组件安装入口；`127.0.0.1` 链接只适用于这台 Mac。

**旧版升级：**打开 iPhone/iPad 的 Scriptable 原“课期”脚本，用本目录新版全部代码替换并运行一次，原主屏幕组件可继续使用。手机上的旧脚本不会因为 Mac 源码更新而自行升级；升级完成后仍由系统安排刷新，不需要每天手动运行。

1. 在设备安装 [Scriptable](https://apps.apple.com/cn/app/scriptable/id1405459188)，打开一次。
2. 将同目录的 **课期.js** 通过隔空投送或 iCloud Drive 发到设备。在 Scriptable 中新建脚本，粘贴文件中的全部代码，名称设为“课期”。也可在系统分享菜单中选择 Scriptable 导入脚本；是否出现该入口取决于设备上的分享菜单配置。
3. 先在系统“日历”App 中确认“作业与考试”日历和近期作业已出现，iCloud 日历已启用。
4. 在 Scriptable 内点击运行“课期”，本人授予日历的**完整访问权限**（只允许添加日程不足以读取）。脚本本身只执行读取。若未弹窗，在系统“设置 → App → Scriptable → 日历”检查权限；不同系统版本路径可能不同。
5. 返回主屏幕，长按空白位置，添加 **Scriptable** 小组件，选择小、中或大号；iPad 也可选择超大号。
6. 长按刚添加的组件，选择“编辑小组件”，在 **Script** 一栏选“课期”。**Parameter** 通常留空；尺寸会自动匹配组件。点击后会进入 Scriptable，重新读取本机日历并以大号预览显示最多 5 项，并非显示所有记录。
7. **iPhone 和 iPad 各自完成授权、添加组件和选择脚本。**即使脚本由 iCloud Drive 同步，系统权限和主屏幕配置也需要逐台设置。

在 App 内运行默认预览中号。可将代码顶部的 `PREVIEW_SIZE` 改为 `small`、`medium`、`large` 或 `extraLarge` 预览其他大小；主屏幕实际尺寸始终优先。在支持传入组件参数的预览场景，也可直接把 Parameter 设成上述尺寸之一。

手机查看**已经到达本机的日历记录**时，无需与 Mac 连接同一 Wi-Fi，也无需让 Mac 程序保持前台。Mac 仍需开机、联网并保持平台登录有效，才能按计划采集新作业并更新 iCloud 日历。手机无法自行读取学习通或希冀。

## 同名日历与错误排查

- 找不到日历：先打开系统日历，确认 iCloud“作业与考试”确实已在本机出现，再运行脚本。脚本不会自动创建新日历。
- 读取失败或没有授权：在 Scriptable 内运行一次并检查系统权限。读权限不足时不会把结果当作空清单。
- 多个同名日历：脚本不会合并或随意选第一个。最容易的办法是在系统日历核对账号后，为其他同名日历改名，保留目标名称唯一；Mac 程序使用的专用日历必须保留“作业与考试”这个名称。也可以在 Scriptable 内运行查看提示中的标识，核对后在这台设备小组件的 Parameter 填写 `{"calendarId":"目标日历标识"}`；需要指定预览尺寸时可填 `{"size":"large","calendarId":"目标日历标识"}`。也可将代码顶部 `CALENDAR_IDENTIFIER` 填入该标识。标识可能因设备而不同，请分别核对。
- 在手机修改考试时间后报错：旧脚本把日历开始时间强制当成截止时间。用安装页的新版完整代码替换原“课期”脚本，运行一次即可，原主屏幕组件可继续使用。新版同时识别截止占位事件和与备注相符的真实考试区间，例如 09:00–11:30 会显示 09:00 开考、11:30 结束，并按 09:00 计算倒计时。
- 时间不一致：新版依据 Mac 备注中的开考、截止或上课时间显示安排，时间冲突会提示核对。请在 Mac 程序核对、修改对应记录；手机改动不会回传。手动录入和平台读取的考试在填写开考时间后，会同步为开始至结束的日历区间，提醒以开考时间计算。
- 单条备注格式异常：只跳过这条记录，其他待办继续显示，底部提示“N 项异常”；全部记录都异常时显示“有记录需要核对”，不会显示成没有待办。请核对记录后再同步。普通私人日程没有课期固定备注格式，不会被小组件展示。
- 组件没有立刻变化：打开 Scriptable 手动运行检查本机当前记录；组件更新节奏由 iOS/iPadOS 调度，省电、低电量等情况下可能延迟。代码设置的 15 分钟只是最早刷新时间，不是每 15 分钟准时刷新。

Apple 日历负责考试开考前、作业截止前和上课前 48／24／2 小时提醒。本版继续使用日历通知，无需安装原生闹钟 App。脚本不承诺组件上的分钟数字实时跳动。

组件底部明确区分两个时间，均按北京时间显示：

- **平台同步 MM/DD HH:mm**：Mac 最近一次完整成功读取平台的时间，来自 Mac 写入日历备注的“平台最近成功同步”字段。它不使用任务修改时间，也不使用小组件当前时间推测。
- **平台尝试 MM/DD HH:mm · 部分／未完成／读取中**：尚无可验证的完整成功时间时，显示 Mac 最近尝试读取平台的时间及结果。这不代表完整同步成功；小号精简为“尝试 MM/DD HH:mm（部分）”等形式。
- **日历读取 HH:mm**：本次脚本成功读取 iPhone/iPad 本机日历的时间。这个时间更新，不代表 Mac 刚刚检查过平台。

iCloud 传播过程中不同记录的同步时间可能不一致，组件保守显示查询范围内所有课期记录中最早的有效时间。完整成功字段不齐全时，仅当所有记录都有合法尝试时间和结果，才回退显示最早的“平台尝试”时间。两个字段均无法验证时显示“平台同步时间未知”；无时区、无效日期、未来时间、重复字段均不采信。没有课期事件时也显示未知，因为空日历无法证明 Mac 已检查过平台。完整成功时间已知但之后尝试未完整完成时，在成功时间旁补充“部分”“未完成”或“读取中”。旧版日历备注会在 Mac 下一次成功同步日历后更新。读取失败时明确显示“日历读取失败”，不会显示成功读取时间。中号在同一行列出两个来源，小号、大号和超大号分两行显示。

## 已验证和待验证

在项目目录运行 `node tests/test_widget.js` 可离线复核 158 个模拟场景；运行 `TZ=America/Los_Angeles node tests/test_widget.js` 检查设备时区变化。测试覆盖四种尺寸、深浅色、24h/2h 边界、已完成移除、读取错误、考试开考倒计时、跨日排序、进行中与缺开考时间、真实区间、改时冲突、单条坏备注隔离，以及平台时间与设备读取时间的区分、日期校验、重复字段、部分/失败尝试和混合传播状态，不访问系统日历或平台账号。

已按 Scriptable 官方 API 编写，并做 JavaScript 语法和模拟数据行为检查；目前没有在用户的 iPhone/iPad 上运行，最终字体布局、权限流程及系统刷新仍需设备端验收。此脚本面向主屏幕组件，未设计锁屏组件。
